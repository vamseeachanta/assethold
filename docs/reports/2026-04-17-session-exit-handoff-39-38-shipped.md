## Decisions made (not obvious from code)

### #39 — scope redirect from "edit 3 modules" to "new orchestrator"
The issue body said edit `alert_engine.py`, `trend_detector.py`, `dashboard.py` to plumb kwargs through. Adversarial review confirmed (verified by Claude + Codex + Gemini against the codebase) that **none of those three modules construct `StockDataSource`** — `alert_engine.build_alerts(ticker, trend_events, insider_flags)` takes pre-computed dicts; `TrendDetector.analyze(df)` and `dashboard.build_*_chart(df, ticker)` take pre-fetched DataFrames. Only `analysis/daily_strategy/fetcher.py:80` constructs `StockDataSource` in production. Plan introduced a new `WatchlistRunner` orchestrator instead. **User approval of the plan = approval of this redirect**, recorded explicitly in the governance comment on #39.

### #39 — `lookback_days: 90` is the default historical window
Picked because MA-50, RSI-14, and volume-spike baselines all converge within 90 trading days. The actual `StockDataSource.fetch(ticker, start_date, end_date)` requires explicit dates (this was a v1 plan defect — the original `fetch(ticker)` was unimplementable). `lookback_days` is now a `settings:` knob and a `--lookback-days` CLI override.

### #39 — clock injection over `date.today` monkeypatching
v1 plan tried to monkeypatch `date.today` for `_date_range()` testability. Codex v2 review pointed out `datetime.date` is C-implemented so `monkeypatch.setattr(date, "today", ...)` fails. v2.1 added `now: Callable[[], date] = date.today` constructor parameter. Tests pass `now=lambda: date(2026, 4, 17)`.

### #39 — subprocess-isolated lazy-import test pattern
v1 plan proposed `monkeypatch.setattr(sys.modules["assethold.utils.market_hours"], None)`. Adversarial review correctly noted shared-pytest-process state contamination — `pandas_market_calendars` may already be loaded by other tests. v2 replaced with `subprocess.run([sys.executable, "-c", probe_script])` running a fresh interpreter. The same pattern applies to #38's Item 1 (`cache.ohlcv_ttl()` lazy-import test).

### #38 — `_next_event(ts, column, label)` not `_next_event(ts, column)`
v1 plan had `f"No NYSE {column}..."` — would have changed `ValueError` text from `"No NYSE market open found..."` to `"No NYSE market_open found..."` (with underscore). Both Claude and Codex flagged this as contradicting "no behavior change in production code". v2.1 added the `label` parameter so wrappers pass `"market open"` / `"market close"` and original text is byte-identical.

### #38 — `pytest.ini` already has the `slow` marker (don't re-register)
v1 plan said "register `slow` in pytest.ini" — both reviewers caught that `pytest.ini:13` AND `tests/conftest.py:275` already register it. Item 5 reduced to "apply the decorator only" (to **both** sibling slow tests: daily_strategy + watchlist_runner from #39).

## Repo ops gotchas

- **`gh issue close` silently drops comments on already-closed issues.** When user closes via `gh issue edit`/UI before agent runs `gh issue close --comment "..."`, the comment is lost. Workaround: `gh issue reopen` → `gh issue comment` → `gh issue close`. Hit this once this session; recovered by reopening both #38 and #39, posting the final-state comments, and re-closing.
- **Auto-sync cron picks up untracked cache files.** Integration tests (`test_no_intraday_flag_does_not_check_market_hours` in both `_intraday.py` files) run real `yfinance` fetches and write to `data/stocks/cache/`. The auto-sync process (commit `7e9f1bf` this session) committed those to `main`. **Recommendation:** add `data/stocks/cache/*.csv` and `data/stocks/cache/*.json` to `.gitignore`, OR mark the slow tests `@pytest.mark.network` and exclude from local quick runs.
- **Wall-clock test flakes.** `test_cli_no_flag_falls_back_to_config` (added in #39) silently passed when market was open and failed when closed because it didn't stub `is_market_open`. Symmetric fix in `7e1b716`. Pattern: any CLI test that crosses the `--intraday` / config-fallback branch must stub `is_market_open` to make the test deterministic. Symmetric `test_cli_intraday_overrides_config_false` already had the stub — should have copied the pattern at #39 time.
- **`pytest.ini` takes precedence over `pyproject.toml`'s `[tool.pytest.ini_options]`.** The session header always shows `WARNING: ignoring pytest config in pyproject.toml!`. Drift between the two files exists today (different marker lists, different `--cov-fail-under`); removing `pytest.ini` later will be a breaking change.
- **Codex retrieval-block on local-only plans.** Codex CLI cannot read local files via `bash` (sandbox denies bwrap). It only reads via `github_fetch_file` MCP tool, which requires the file to exist on a GitHub branch. **Lesson:** commit + push plan files to `main` BEFORE dispatching Codex review. Otherwise it spends 5+ minutes spinning on github_search and produces a "retrieval insufficient" verdict. (Spent significant time on this in #39 v1; resolved for #38 by pushing first.)
